# Curated external standards and practice references

These sources are optional lenses and evidence references. They never override accepted M21 project contracts or create frontmatter fields automatically.

## Cross-cutting

- [Agent Skills specification](https://agentskills.io/specification) — portable skill structure and progressive disclosure.
- [Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf) — portable knowledge-bundle context.
- [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) and [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174) — requirement language when normative strength matters.

## Business and Business Solution

- [UK Government Service Standard](https://www.gov.uk/service-manual/service-standard) — outcome-oriented, inclusive, whole-service practice.
- [Service Manual: user research](https://www.gov.uk/service-manual/user-research) — research planning, evidence, and ethics.
- [OECD Systems Innovation resources](https://oecd-opsi.org/guide/systems-approaches/) — systems approaches and intervention context.

## Visual Design and Application Experience

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) — normative web accessibility criteria.
- [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) — accessible interaction pattern guidance; prefer native semantics first.
- [WAI Accessible Platform Architectures](https://www.w3.org/WAI/APA/) — accessibility implications of platform design.
- [Design Tokens Community Group format](https://www.designtokens.org/tr/drafts/format/) — interoperability reference when a project adopts structured design-token exchange.

## System Design, Architecture, and Application Architecture

- [C4 model](https://c4model.com/) — context and container communication; use as a projection lens, not canonical ownership.
- [NIST Cybersecurity Framework 2.0](https://www.nist.gov/cyberframework) — security outcome framing.
- [OWASP Threat Modeling](https://owasp.org/www-community/Threat_Modeling) — trust, threats, mitigations, and validation.
- [OWASP Application Security Verification Standard](https://owasp.org/www-project-application-security-verification-standard/) — application security requirements and evidence.
- [NIST Privacy Framework](https://www.nist.gov/privacy-framework) — privacy risk and data-processing outcomes.

## Components, Code Design, and Implementation

- [Semantic Versioning](https://semver.org/) — public contract compatibility when the project adopts semantic versions.
- [Consumer-Driven Contracts](https://docs.pact.io/) — one implementation approach to cross-service contract evidence, not a required tool.
- [NIST Secure Software Development Framework](https://csrc.nist.gov/Projects/ssdf) — secure development practices and evidence.
- [SLSA](https://slsa.dev/) — software supply-chain integrity levels and provenance.

## Deployment and operations

- [Google SRE books](https://sre.google/books/) — SLOs, error budgets, incident response, and reliable operations.
- [OpenTelemetry](https://opentelemetry.io/docs/) — vendor-neutral telemetry concepts and semantic conventions.
- [OpenSSF Scorecard](https://securityscorecards.dev/) — evidence-oriented supply-chain risk checks.
- [CIS Benchmarks](https://www.cisecurity.org/cis-benchmarks) — environment hardening references when applicable.

## Use discipline

When citing one of these:

1. Name the specific decision or risk it informs.
2. Distinguish normative requirement from optional guidance.
3. Record project-specific interpretation and evidence.
4. Avoid copying a framework's taxonomy into M21 metadata without an accepted workspace use.
5. Prefer the current published version and note material version assumptions.
